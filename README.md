# ssx3-recomp

Static recompilation of **SSX 3** (original Xbox, PAL) to a native Windows
executable with [xboxrecomp](https://github.com/sp00nznet/xboxrecomp), plus a
byte-exact per-function disassembly for hand decompilation.

**Current state: playable at a steady 60 FPS.** It boots straight to the
title (intro movies skipped by default), and every menu works -- Options and
its sub-screens, character setup, Equip Gear, Rider Details, Music, Conquer
the Mountain. Saving and loading use `game\UDATA` like the console's hard
disk. All Peak 1 courses play (Snow Jam, Metro-City, Happiness, Freestyle)
with HUD, rider shadows and audio at **60 FPS** (p99 frame ~19 ms): the
Vulkan renderer (default) runs the game's vertex programs and pixel
combiners on the GPU, and frames are shown through D3D11 with vsync. A
keyboard or an XInput controller works as player 1. The Linux port and the
Vulkan renderer are by Corné Dorrestijn (docs/LINUX.md, docs/VULKAN.html).

![Metro-City at 60 FPS](docs/screenshots/29-metro-city-60fps.png)

No game data or game code is in this repository. You need your own rip of the
disc (`default.xbe` + `data/`); everything derived from it is regenerated by
`scripts/regen.ps1` (Windows) or `scripts/regen.sh` (Linux/WSL).

## Build

**Windows only** (no WSL): Visual Studio 2022 with the C++ workload, the
Vulkan SDK (`winget install KhronosGroup.VulkanSDK`), git and Python 3.9+.

```powershell
git clone <this repo> ssx3-recomp; cd ssx3-recomp
# put your rip in game\ : game\default.xbe and game\data\
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1   # toolkit (pinned + patched) in ..\xboxrecomp, Python venv
powershell -ExecutionPolicy Bypass -File scripts\regen.ps1   # analysis, decomp\ split, src\recomp\gen\ C lift (~7 min)
tools\build.bat                                              # MSVC + Ninja, ~18 min the first time
tools\play.bat
```

**From WSL** (how the project is developed; the build itself is the same
MSVC build on the Windows side):

```bash
scripts/setup.sh                 # toolkit clone (pinned + patched) and Python venv
scripts/regen.sh                 # needs the rip in ../SSX3/
scripts/sync-windows.sh --game   # copy to C:\Code\Xbox for the MSVC build
cmd.exe /c 'C:\Code\Xbox\ssx3-recomp\tools\build.bat'
```

The toolkit is pinned at v0.13.1 (`193e299`) with this project's fixes in
`patches/xboxrecomp-local.patch`. Linux: docs/LINUX.md.

## Play

Run `tools\play.bat` on Windows. Keyboard (the game window must have focus):

| Key | Pad | Key | Pad |
|---|---|---|---|
| Enter | Start | Backspace | Back |
| Z X A S | A B X Y | Q E | White / Black |
| 1 3 | Left / right trigger | Arrows | D-pad |
| Numpad 8/4/2/6 | Left stick | I J K L | Right stick |

Two controllers plugged in at start make Multi Play (2-player split-screen)
available. Keys and controller buttons can be remapped: copy `keys.example.ini` to
`keys.ini` and edit it. An Xbox/XInput controller needs no setting (rumble included). The game renders at
1440x1080 (full-HD height; the game itself is 4:3) -- `RECOMP_RES=480` for
the original 640x480, `RECOMP_RES=1440` / `2160` for more; the window opens
as large as fits, F11 for fullscreen. **Widescreen** (this branch, on by default): races
and free-roam fill your monitor's shape -- 16:9, 21:9 or 32:9 (the game's
camera is widened, so you see more, nothing is stretched; the HUD keeps its
shape), rendered at your monitor's height; menus and loading screens stay 4:3
with black bars. `RECOMP_WIDESCREEN=16:9` (or any `W:H`) forces a shape,
`=0` gives 4:3; `RECOMP_RES` overrides the height. The window
opens at 2x (`RECOMP_WINDOW_SCALE`), can be resized, and **Alt+Enter** or
**F11** toggles borderless fullscreen; the picture keeps its 4:3 shape
(`RECOMP_PRESENT_FILTER=point` for sharp pixels). Each run's log is kept in
`logs\` (newest 40); a crash also leaves a minidump there
(`crash_<time>.dmp`, open it in Visual Studio next to `build\ssx3_recomp.pdb`). `RECOMP_GPU=sw` uses the software rasteriser instead of
Vulkan; `RECOMP_SKIP_INTRO=0` plays the intro movies.

## Known issues

- Peaks 2 and 3 are locked on a fresh save (the game's own progression).
- Riders look a little flatter than on a real console capture (see
  ROADMAP, "Phase 5"); the game's display gamma ramp is applied.
- Under heavy parallel test load (8 instances) a run can occasionally miss
  the controller on the title screen; not seen in normal play.
- `RECOMP_GPU=sw` (software renderer), `RECOMP_GPU_VSH=0` (vertex programs on
  the CPU) and `RECOMP_D3D_PRESENT=0` (GDI window) switch the newer paths off
  if one misbehaves.

## Testing

All scripted runs are silent and ignore a real controller, so the PC stays
usable while they run (Windows, from the repo root):

- `tools\race_test.ps1 -Runs 1 -RaceSec 20 -Snap x.png [-Rider N -Mode N -Event N]`
  -- boot to a race, ride, screenshot.
- `tools\cycle_test.ps1 -Cycles 12` -- race, pause, quit to the title, again.
- `tools\menu_test.ps1 -Steps "y,wait,down,a"` -- menu presses with a
  screenshot per step.
- `tools\race_par.ps1 -Instances 8 -Runs 2` -- parallel boot-to-race batches.

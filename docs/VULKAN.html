SSX 3 Vulkan renderer

Replaces the software rasteriser (nv2a_pb_exec.c) on Linux. Code: src/vk/. Target: Honeykrisp (Asahi M2), Vulkan 1.3 dynamic rendering. Branch vulkan, worktree .claude/worktrees/vulkan.

cmake -S src/vk -B build-vk -G Ninja && ninja -C build-vk && build-vk/vkr_selftest out.bmp

Approach

The executor keeps parsing the pushbuffer, tracking state and running vertex programs on the CPU (nv2a_vsh_run). Its post-program vertices (Nv2aVshOutput: pixel-space pos, w, d0/d1, fog, 4×tex) go to vkr_draw instead of the per-pixel rasteriser. The vertex shader re-expands pos to clip space (xy/size*2-1, z/zmax, w) so the GPU clips and interpolates perspective-correctly. Raster was ~65–70% of executor time, VSH ~15%.

Milestones

  • 1. Context, offscreen colour+depth, indexed draws, readback (vkr_selftest).
  • 2. Backend hook (nv2a_backend.h, in the toolkit patch): draw / clear / flip callbacks; src/vk/vkr_backend.c registers with RECOMP_GPU=vk. Boots to the frontend; frames come from Vulkan (white: no textures yet). Only the main 32-bit linear surface goes to Vulkan; other targets stay software.
  • 3. Surfaces keyed by guest address (colour/depth, swizzled RTs); present by writing the front surface to guest memory (existing SDL present), later a direct swapchain.
  • 4. Textures: stage 0 done (decoded by the executor's sample_tex, cached by content hash, push descriptors, sampler per wrap/filter); intro movie renders. Left: stages 1-3, mips, cube maps, border colour, render-target-as-texture, per-frame hash cost.
  • 4b. Blend (factors/equation/constant), colour write mask, alpha test, depth func: wired (pipeline cache keyed by blend state).
  • 5. Register combiners → GLSL: interpreter port of nv2a_combiner.c (words in a per-draw UBO, one shader), 4 texture stages with project2D/passthru modes, fog in the vertex shader. Select Character renders correctly. Left: cube maps, bump/dot-product stage modes, clip-plane stage, border colour, stencil.
  • 6. Vertex programs → SPIR-V (drops the CPU interpreter).
  • 7. Differential test vs software output (screenshot suite).

Notes

  • The shared ../xboxrecomp clone has uncommitted edits that differ from patches/xboxrecomp-local.patch (e.g. RECOMP_LOOP_QUANTUM); the main tree's session is using it. Do not edit it from this worktree: use a separate toolkit clone (XBOXRECOMP_DIR) at base 193e299 + this worktree's patch, and regenerate the patch from there.
  • Not covered yet: render targets sampled as textures or read by the game (rider shadow maps) — arrives with surface tracking. They are drawn by the software rasteriser and re-decoded as textures each frame: the biggest remaining executor cost after vertex programs.
  • Frames are pipelined: vkr_flip_submit submits a frame and recording continues in the other of two frame slots; a backend thread waits for it and copies it into the flipped surface a few ms after the flip.
  • Lens flare: the main view is not rasterised in software, so visibility tests report 0 pixels and the flare is hidden (as before). With Vulkan installed, LensFX's test poll does not wait (sub_001F8760 wrapper, same 0.0 answer). Showing the flare needs Vulkan occlusion queries.
  • Depth: with CONTROL0 Z_PERSPECTIVE (the race sets it) the depth test uses w, written as gl_FragDepth = w / zmax. The race's z is hyperbolic and sits within 1% of the far end, too coarse in the distance. The software rasteriser still uses z.
